HOW THE NEXT VERSION GETS HERE

Preserve. Review.
Prove. Release.

  1. 01

    Keep the source

    Separate source folders, original history intact. No silent code or account-data merge.

  2. 02

    Review the change

    Changes go through pull requests and cross-side review, not direct edits to the live version.

  3. 03

    Check the result

    Record what was actually tested. Provider actions and device delivery need their own proof.

  4. 04

    Publish a release

    Only after the release is ready. Existing services stay separate until a joint cutover decision.
